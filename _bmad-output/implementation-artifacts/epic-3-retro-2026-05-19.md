## What worked

### Q-pin-at-Task-0 as a universal pattern, all Option A

Every Epic 3 story landed Q1–Q9 pre-dev pins via `AskUserQuestion` at the top of the dev pass. **Every single Q across all 8 stories resolved Option A** — the spec-author's recommended path. Worth keeping. The pattern says the create-story pass is producing high-confidence recommendations the dev pass doesn't need to deviate from, and the Q-pin ritual is the right unblock surface for the few decisions that *do* deserve human eyes (NFR9 amend, refactor scope, commit strategy, test-cost trade-offs).

### `feedback_create_story_cross_check` paid for itself

The memory entry filed in Epic 2 retro A3 caught spec-narrative drift in **five out of eight** Epic 3 stories. Concretely:
- **Story 3.2 / 3.4:** `DISPATCH_NORMAL_COUNT` off-by-one in spec narrative (auto-computed value was correct; narrative was wrong).
- **Story 3.3:** `status_compose_scratch` story spec said 32 B; fileio's legacy `ASSERT $ - fileio_status_scratch >= 48` proved 48 B floor.
- **Story 3.6:** Test fixture arithmetic (`yank_length 9 vs 10` jagged block; fixture `32 B vs 33 B` c-line).
- **Story 3.7:** `undo_length 17 vs 18` and `4 vs 5` — pre-walk vs post-walk semantic.
- **Story 3.8:** AC6 LINE-arm projection wording contradicted Q5 contract.

Dev pass caught all five before they reached production. **The cross-check works.**

### Shared-helper extraction saved Story 3.8

Story 3.6 landed with 458 B headroom. Story 3.7 ate 104 B → 337 B. Story 3.8 first build came in **67 B OVER** the 8192 B ceiling. Resolution: extracted `_visual_op_block_project_rect` from Story 3.6's BLOCK arm (60 B of duplicated projection logic) into a shared helper used by both 3.6 and 3.8. Saved 64 B + retired a dead-store write to `visual_op_block_cols`. Landed 13 B under ceiling. **The "spec-projected shrink-down" pattern from story planning is real and bankable** — the planning text predicted this exact relief valve.

### Standalone code review pass added 5× over Epic 2

Epic 2 ran 0 standalone code reviews (every story was single-dev-commit). Epic 3 ran 5 (3.2, 3.5, 3.6, 3.7, 3.8). Real finds that landed as patches:
- **3.6:** BLOCK arm cursor-clamp gap on jagged-top selections (+17 B patch).
- **3.6:** `visual_d-yank-too-large` test missing deletion-proceeds assertion (SR6 invariant pinning).
- **3.6:** `parser_visual_d-dispatch` missing `UNDO_KIND_DELETE` assertion.
- **3.5:** `ASSERT VIS_CHAR == 0` pin for the fall-through; multi-digit RxC banner test.
- **3.7:** Empty-buffer / gapbuf overflow / dispatch-arm-`<` test fixtures.
- **3.2:** AC6 parser-state-clear coverage gap; AC2 `command_submode` pure-reader assertion.

Adversarial-review surface is now load-bearing for the visual-mode complexity.

### `enter_normal_mode clobbers status` captured + reused

Story 3.6 hit it first: `JP enter_normal_mode` unconditionally writes `msg_mode_normal` which clobbers any prior status (e.g. `msg_yank_too_large`). Resolution was a `visual_op_block_yank_ok` flag + manual `LD A, MODE_NORMAL ; LD (mode_byte), A ; JP parser_clear` tail. Filed as `feedback_enter_normal_mode_clobbers_status.md`. Same pattern then surfaced in 3.7 and 3.8 — the memory entry made the fix mechanical both times.

### Hardware UAT every story, every time, zero fail-iterations

8 stories, 8 hardware UAT confirmations. Step counts: 11 (3.1), 15 (3.2), 17 (3.3), 13 (3.4), 22 (3.5), AC13 (3.6), 26 (3.7), 23 (3.8). UAT scripts pasted inline at dev-handoff per `feedback_uat_inline_at_dev_handoff`. **Zero UAT-fail iterations across the entire epic** — every UAT script passed on first hardware run. The combined NFR8 (BDOS rc check) discipline + Story-2.4 R/O precheck + Q-pin pre-dev resolution produced UAT scripts that matched real behaviour.

### Speed: 2 days vs Epic 2's 9 days

Possibly the smallest end-to-end Epic VIBE will see again. Visual mode is intrinsically narrow surface compared to authoring/save/undo: handlers consume `(anchor, cursor)` and route through existing `edits_*` / `undo_*` / `gapbuf_*` primitives. The "stub-now-wire-later" pattern from Epic 2 also pre-baked the integration points (the `visual_*` STUB hook sites were already in place before Epic 3 dev began).

## What hurt

### NFR9 cliff edge — 13 B headroom is unsustainable

Story 3.6 projected 7517 B; landed 7734 B (+217 B drift). Story 3.7 ate 104 B (337 B headroom). Story 3.8 first build went OVER the ceiling; recovered to 8179 B / 13 B via the shared-helper extraction.

Drift sources matched Epic 2's pattern: **projections one-directional, always over, never under**. Spec-projected mid-estimates structurally underweighted the BH3 helper (3.6), AC7 refusal-flag refactor (3.6), BLOCK arm PUSH/POP DE bracketing across `motion_byte_at_logical` (3.5 / 3.6 / 3.8), shared-tail compose growth (3.4). Same systematic optimism Epic 2 flagged; the 8192 B amend bought enough headroom to hide it for 7 stories before 3.8 surfaced it sharply.

**Epic 4 cannot begin without an NFR9 amend.** Action item below.

### Spec-narrative drift moved from "occasional" to "near-universal"

Caught in 5/8 stories (vs 4 across Epic 2's 13 stories). The cross-check memory caught them all, but the recurrence rate says the create-story pass is producing AC arithmetic by one-line abstraction rather than computing against the actual source state. The dev pass is doing reconciliation work silently — same observation as Epic 2 retro, scaled up.

The fix is not "stop trusting create-story" — the AC narrative quality is otherwise high and the Q-pins resolve cleanly. The fix is to **make the cross-check the dev pass's explicit Task 0 step** so the reconciliation isn't silent.

### DE-trash gotcha is now a 4+ instance pattern

Story 2.6 hit it twice (`motion_dollar` + `motion_find_line_n`). Story 3.4 hit it a third time (`visual_count_lines` — +8 B over spec). Story 3.5 hit it a fourth (`visual_count_block_dims`). The motions.asm header still doesn't document the DE-trash invariant prominently — Epic 2 carry-forward #1 stayed unaddressed across all 8 Epic 3 stories.

A comment-only fix in `motions.asm`'s module header (highlighting that `motion_byte_at_logical` trashes DE while preserving BC) costs near-zero NFR9 bytes and pins the contract surface visible at every consumer's read. Action item below.

### Caller-side bound hardening pushed forward

Story 3.8's code review surfaced 4 shared-pattern findings inherited verbatim from 3.6/3.7:
1. CHAR arm passes `HL+BC > file_length` to `gapbuf_case_toggle_range` on empty buffer.
2. BLOCK walker enters past-EOF offsets when `top_ls >= file_length` (self-terminates but undocumented).
3. BLOCK jagged-top cursor clamp is single-step `DEC HL` — insufficient when `top_ls + col_min` overshoots top-row EOL by >1.
4. BLOCK with `cursor==0` + leading LF skips clamp via `OR L ; JR Z` shortcut.

All four shipped in 3.6/3.7 through hardware UAT. NFR9 cliff (13 B) made in-story remediation impossible at 3.8. **Deferred to Epic 4** — these are real correctness gaps in edge cases the UAT didn't surface.

### Unit-test coverage gaps mounted

Hardware UAT confirmed end-to-end correctness on every story, but unit-test layer accumulated 10+ gaps on Story 3.8 alone: CHAR backward paths (`cursor < anchor`), boundary-at-`file_length`, LINE last-line-no-LF (`.at_eof` CF=1), LINE 1-line selection, BLOCK 1×1 rectangle, BLOCK with `top_ls >= file_length`, gap-crossing primitive calls (range straddles `gap_start`/`gap_end`), no-op undo preservation through `op_undo` replay round-trip, BLOCK no-op all-digit clobbering prior undo with TOO_LARGE, replay correctness under interleaved mutations.

**Hardware UAT is masking unit-level holes** — inverted shape of Epic 2's iz-cpm/real-CP/M divergence finding. Same lesson, opposite direction: each test layer catches things the other misses.

### BLOCK arm complexity is the load-bearing risk surface

`_visual_op_block_arm` = 405 B (Story 3.6, before shared-helper extraction). The single largest routine in `visual.asm`. BH3 jagged-line clip, multi-region undo TOO_LARGE refusal, per-row clipped delete with shift tracking, jagged-top cursor clamp. Future visual-mode regressions will most likely live here. Multi-region undo is the path that would unlock VIS_BLOCK `c` typed-content recovery (currently `c` over a block selection types fine but `u` afterward surfaces `msg_undo_too_large` and does NOT unwind the typed content — known limitation per AC8 of Story 3.6).

Document amend-history block in PRD §NFR9 (sibling to the 3072 → 5120 → 5760 → 6400 → 8192 amends) and update the 5 architecture.md callsites + the `make sizes` percentage display in `Makefile`.

### A2. DE-trash invariant docstring on motions.asm header (Ant agreed)

**Owner:** Amelia (dev) | **Trigger:** Bundle into the hardening story (A3 below) OR standalone before it

### A3. First story of Epic 4 = visual-mode hardening pass (Ant agreed)

**Owner:** Story spec author (Bob/Amelia depending on which planning skill is used) | **Trigger:** First story of Epic 4

Bundle into a single hardening story before any new feature work:

**Code hardening (4 inherited findings):**
- Patch `gapbuf_case_toggle_range` with a 5-B `file_length=0` short-circuit at primitive entry (covers caller-bound finding 1 + transitively 2).
- Replace BLOCK jagged-top cursor clamp's single-step `DEC HL` with a `motion_byte_at_logical`-driven loop (finding 3).
- Remove the `OR L ; JR Z` shortcut in BLOCK clamp or guard it (finding 4).

**Test-coverage hardening (10 gaps from Story 3.8):**
- CHAR backward path; CHAR boundary at file_length; LINE last-line-no-LF; LINE 1-line selection; BLOCK 1×1; BLOCK top_ls >= file_length; gap-crossing primitive call; no-op undo replay round-trip; BLOCK no-op all-digit clobbering; replay correctness under interleaved mutations.

Mirrors Epic 1's risk-closure-first pattern (technical-risk stories landed before any feature stories). NFR9 budget projection: ~100-200 B for the four code fixes; 0 B for the test additions.

### A4. Make cross-check the dev pass's explicit Task 0 step (Ant agreed implicitly via the discussion)

**Owner:** Amelia (memory custodian) | **Trigger:** Update `feedback_create_story_cross_check.md` to elevate from "be aware of drift" to "Task 0 reconciliation step before any code changes"
