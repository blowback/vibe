## Deferred from: code review of story-1.3 (2026-05-09)

- **`search_pattern` / `ex_buffer` length-byte convention has no compile-time consumer enforcement.** Buffers reserve `1 + N` bytes (1 length prefix + N payload), documented in comments only. A consumer that reads `SEARCH_PATTERN_BUFFER` bytes from `search_pattern` instead of `search_pattern + 1` reads the length byte as data with no build-time signal. Belongs in ex/search consumer stories (2.1, 3.1) — add a named offset symbol (`search_pattern_text EQU search_pattern + 1`) when those stories first read the buffer. (Source: Blind Hunter.)
- **Static state has no zero-initialization story.** CP/M `.com` files do not zero TPA; `mode_byte`, `gap_start`, `cursor_offset`, `buffer_dirty`, etc. start as whatever garbage the previous program left. The current `RET`-stub doesn't read state, so it's inert today, but Story 1.4+ that reads any byte before writing reads stale RAM. Story 1.12 (init/teardown) must zero the static block on entry. (Source: Blind Hunter.)
- **No alignment / page-crossing consideration for `shadow_buffer`.** A page-aligned `shadow_buffer` enables an `H = row + base_high` render fast-path; the current layout makes no attempt to pad. Whether the win justifies the slack belongs to the render pipeline story (1.11) where indexing strategy is decided. (Source: Blind Hunter.)
- **Mode-state protocol undocumented.** The semantic relationship between `pending_operator`, `pending_motion_prefix`, `visual_submode`, and `count_accumulator` is not pinned in code or comments — whether they're orthogonal axes, mutually exclusive states, or sub-states of a state machine requires reading multiple stories' worth of context. Document in mode-dispatch / command-parser stories (1.9, 1.10) where the protocol is first implemented. (Source: Blind Hunter.)
- **`inc/state.inc` has no `IFDEF`-style re-include guard.** sjasmplus's natural EQU single-assignment catches accidental double-include with a duplicate-symbol error, but a defensive guard convention across all headers would catch it earlier and produce a more diagnostic message. Project-wide convention question — defer to a future structural-cleanup pass. (Source: Blind Hunter + Edge Case Hunter.)
- **No per-section sentinels with ASSERTs catching a missed `static_off` advance.** A forgotten `static_off = static_off + N` line silently aliases two adjacent fields with no build-time error. Adding `small_state_end`, `word_state_end`, `buffer_block_end` sentinels with `ASSERT` checks on their offsets would catch this. Defer until the layout grows further or a near-miss occurs. (Source: Blind Hunter + Edge Case Hunter.)
- **No file-naming or comment convention to distinguish EQU-only vs positional `.inc` headers.** state.inc must INCLUDE post-`ORG` (uses `$`); equates.inc / vt52.inc / modes.inc are safe pre-`ORG`. The distinction is documented only in two scattered comments. A naming convention (e.g., `*.eq.inc` vs `*.pos.inc`) or an explicit Header attribute in the AR23 block would make the rule structural. Project-wide question. (Source: Blind Hunter.)

## Deferred from: code review of story-1.4 (2026-05-09)

- **`BIOS_TICK_ADDR` placeholder address overlaps the BIOS jump-table neighborhood.** `EQU 0xFA00` sits six bytes below `BIOS_CONIN EQU 0xFA06`; on a typical CP/M 2.2 BIOS (17 × 3-byte jumps = 51 bytes from base) the tick counter lands inside the jump-table region. Spec Task 1 mandates the architecture-listed placeholder values verbatim, so the value cannot be moved here. Story 1.12 (init/teardown, hardware bring-up) confirms real BIOS-jump-table addresses against MicroBeast docs/disassembly and must lay them out so the tick counter sits outside the jump-table. (Source: Blind Hunter + Edge Case Hunter.)

Adding an `ASSERT TEST_RESULT < BDOS_BASE` would couple the scaffold to a production-header symbol and break the deliberate scaffold/production decoupling per AC2. Revisit when the harness is ported to real hardware (Story 1.12). (Source: Blind Hunter.)

- **Stale `cases/*.com` could survive a clock-skew rebuild.** Obscure: NFS clock drift or `touch -d` games could fool Make's timestamp check, leaving a previous-run's `.com` matched against a newly-edited `.asm`. Address only if seen in practice. (Source: Edge Case Hunter.)
- **`iz-cpm` not on PATH masquerades as universal test failure (rc=127, "command not found" folded into `$out`, no PASS/FAIL match → every case reports `unknown`).** Operational; not a Story 1.6 regression. - **Sentinel could collide with the future production memory map** if a later test INCLUDEs `inc/state.inc` and the production layout grows to occupy 0xCFFE/CFFF. Static check belongs to whichever story first crosses that line. (Source: Edge Case Hunter.)
- **`cases/*.asm` glob picks up Emacs lock symlinks (`.#foo.asm`).** Make's wildcard matches them; sjasmplus then chokes on a symlink to nothing. Rare in practice; switch to `find` if it becomes a problem. (Source: Edge Case Hunter.)

## Deferred from: code review of story-1.7 (2026-05-10)

- **`gapbuf_move_gap` has no debug-build runtime check for out-of-range targets or `gap_size == 0` precondition.** Story dev-notes (Task 5) weighed "ASSERT in debug build" vs "document as caller-responsibility" and chose document-only. sjasmplus `ASSERT` is build-time only (operates on assembly-time constants); a runtime check requires (1) a project-wide `IFDEF DEBUG` build mode and (2) a chosen failure surface (`status_set_message`? halt? trap byte?). Neither exists today. The contract holds for internal callers (insert/delete pass `(cursor_offset)`, always valid by SR2). A misuse from a future story (motions, edits) would silently scribble past the gap on right-shift or read garbage on left-shift. Revisit when a project-wide `ASSERT_DEBUG` macro and debug-build mode land. (Source: Blind Hunter + Edge Case Hunter.)

## Deferred from: code review of story-1.8 (2026-05-10)

- **`input_held_flag` / `input_held_byte` are uninitialised at boot.** First-ever `input_get_key` call returns garbage if the RAM at the EQU'd addresses is non-zero on warm boot — the queue branch fires and returns `(input_held_byte)` without ever polling `BIOS_CONIN`. Static block has no zero-init in Story 1.8; spec explicitly defers init to Story 1.12 (matching the prior Story 1.3 deferral "Static state has no zero-initialization story"). `input_get_key` becomes callable in Story 1.9 (dispatch) and exercisable via the optional AC14 smoke, but no UAT is possible anyway until end of epic 1, so the gap closes naturally when Story 1.12's centralized init lands and zeros the whole static block. (Source: Blind Hunter + Edge Case Hunter.)
- **Queued-Esc bypasses Esc disambiguation (Esc-Esc-Arrow loses arrow synthesis).** When the user types `Esc Esc <arrow-suffix>`, the second Esc gets unrecognised by `synthesize_arrow_key` and stashed in `input_held_byte`; the next `input_get_key` returns it via the held-byte fast path which `RET`s without ever entering `.no_held`'s Esc-comparison branch. The arrow letter on the call after that reads as a plain ASCII byte. Real-keyboard double-Esc is rare in vi and is typically the user's deliberate "assert normal mode" gesture (not an Esc-followed-by-arrow). Fixing requires re-entering Esc disambiguation from the queue path — a meaningful redesign. Revisit only if hardware UAT shows it surfacing as a UX problem. (Source: Blind Hunter + Edge Case Hunter.)
- **`tick_wait_one` hangs forever if the BIOS ISR isn't ticking the counter.** `BIOS_TICK_ADDR` is a W1 placeholder (`0xFA00`, per `inc/bios.inc:65`). If the real MicroBeast BIOS jump-table layout puts the tick counter elsewhere or the ISR isn't armed at startup, a bare-Esc keypress spins forever in `tick_wait_one`'s `JR Z, .spin` with no escape — editor appears frozen. Documented as a Story 1.12 hardware bring-up concern; not the input layer's responsibility. (Source: Edge Case Hunter.)
- **`tick_wait_one` issues unconditional `EI`, clobbering caller's interrupt-disable state.** Today nothing calls `input_get_key` (or `tick_wait_one` directly) with `DI` active. Story 1.12 init is the natural first context where this could matter (BIOS bring-up may run with interrupts disabled). The clean fix is the standard IFF-preservation pattern (`LD A, I; JP PE/PO; PUSH AF; DI; ...; POP AF; ret-with-IFF-restore`) folded into a project-wide convention when 1.12 lands. The current contract is silent about IFF; widen it then. (Source: Blind Hunter + Edge Case Hunter.)
