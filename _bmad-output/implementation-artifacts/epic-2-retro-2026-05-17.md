## What worked

### The stub-now-wire-later pattern for FR45 undo

Stories 2.8 / 2.9 / 2.10 / 2.11 / 2.12 each shipped mutating handlers with documented STUB hook sites — file path, exact line, what state is live at that point, what the inverse-op should record. Story 2.13's dev pass collected all 9 sites and wired them via a shared `undo_record_op` helper. The forward-debt notes read like hand-off comments to future-self, and future-self was able to consume them cleanly. **Worth repeating for Epic 3's visual-state and search-state hooks.**

### AR14 cleanliness held under byte-shaving pressure

Stories 2.9 / 2.10 / 2.11 each had an "Option A cursor-bounce loop vs Option B new gapbuf primitive" decision. All three chose Option A — keep gapbuf surface narrow, accept the per-iter overhead, fold the loop into edits.asm. No regressions, no perf complaints. Only fileio.asm carries documented carve-outs (and the architecture doc was amended in Story 2.6 to acknowledge them); every other module landed clean.

### NFR9 amend discipline

Three formal NFR9 amends (3072 → 5120 → 5760 → 6400 B), each with a full amend-history block in PRD + architecture.md. The team consistently chose "lift the ceiling formally with audit trail" over "shave bytes that compromise safety paths," and Story 2.5 AC14 codified the principle: *"Do NOT skip safety paths to fit (NFR9 explicitly exempts safety per PRD line 850)."* That discipline held through every overshoot.

### Hardware UAT caught real bugs that headless tests masked

Two load-bearing finds:
- **Story 2.4 AC14 step 12:** STAT-marked R/O file → `:w` triggered CP/M 2.2 BDOS R/O intercept → warm-boot → FR52 violation (silent data loss). iz-cpm returns 0xFF cleanly where real CP/M intercepts. Headless was green; hardware caught it; +65 B Step-0 R/O precheck fixed it.
- **Story 2.10 AC7:** Spec narrative predicted vim's `~` empty-line marker; hardware showed VIBE renders past-EOF rows as spaces.

**The iz-cpm/real-CP/M divergence is real.** Every story with a `fileio_` or BIOS-adjacent path needs the hardware loop, not just headless coverage.

### Test sentinel band convention worked cleanly

Stories developed and respected disjoint sentinel bands across modules (motions 0x80..88, paste 0x90..97, parser 0xE0..EC, undo 0xC0..CF). No collisions, no debugging-by-cargo-cult.

### Vibe of authenticity on hardware

Ant's UAT note: vi muscle memory transfers; the editor feels like Home. This is the qualitative outcome the architectural decisions were chasing.

## What hurt

### `test/Makefile` dependency-hygiene gap — flagged 4+ times, never fixed

The `cases/%.com` rule does not depend on `src/*.asm`. Consequences across Epic 2:
- Stories 2.1 / 2.2 silently broke 14 tests at build time (sjasmplus's lax mode emits `.com` files even with unresolved labels). Tests "passed" against zero-byte binaries. Caught by Story 2.3's regression net.
- Story 2.6 dev needed manual `rm -f cases/*.com` to surface the post-stub-retirement reality.
- Story 2.8 dev needed an 80-file batch `python` substitution to add `INCLUDE "../../src/edits.asm"` to every test file.
- Story 2.13 dev needed the same 167-file batch sed for `INCLUDE "../../src/undo.asm"`.

**This is the highest-leverage deferred item in the entire deferred-work.md.** Epic 3 will hit it the moment `src/visual.asm` or `src/search.asm` lands. Action item below.

### Spec-narrative drift from `bmad-create-story`

Multiple stories had AC narrative that didn't match what actually compiled or rendered:
- Story 2.5 AC10: "No new render carve-outs" — UAT iteration 2 added a `.hit_cr` branch in `render_emit_one_row`.
- Story 2.10 AC7: vim-style `~` empty-line marker predicted; VIBE renders past-EOF rows as spaces.
- Story 2.11 test filename `edits_d$-to-end-of-line.asm` collided with sjasmplus's `$` location-counter symbol → renamed.
- Story 2.12 AC10: cursor position off-by-one in `edits_p-fills-buffer` test description.

None escaped to production — dev or review caught all of them. But the pattern says the story-spec pass is producing AC narrative one abstraction layer above what compiles. The dev pass is doing reconciliation work silently.

### NFR9 budget projections consistently optimistic

Every story projected a footprint range; most landed at or above the top of the range. Drivers were typically Z80 calling-convention edges (DE-preservation pushes, BC-preservation PUSH/POP pairs around helper calls, defensive `OR 1`-style set-NZ on fall-through paths). Story 2.11 ran +280 B over (the indent/dedent walk shared helper), forcing the 5120 → 5760 amend. Story 2.13 ran +97 B over the Option A amend, forcing the 5760 → 6400 amend.

This is partially intrinsic — Z80 byte-counting at story-spec time, before the helper-signature contracts are fully nailed down, is hard. But the projections being one-directional (always *over*, never *under*) suggests systematic optimism worth correcting in Epic 3 planning.

### DE-trash contract is load-bearing and easy to miss

Story 2.6 dev hit the same bug twice in the same session: `motion_dollar` and `motion_find_line_n` first drafts both trashed DE inside `motion_find_line_end`. The AR23 Trashes line is authoritative, but the motions.asm header advertises a BC-preservation invariant while omitting the parallel DE-trash invariant. Story 3.1's search dev pass needs to read DE-handling carefully.

## Action items

### A1. Fix `test/Makefile` dependency hygiene (Ant agreed)

**Owner:** Amelia (dev) | **Trigger:** Before Story 3.1 dev pass

Add `src/*.asm` and `inc/*.inc` as dependencies of `cases/%.com`, then run `make clean && make test` from a fresh tree to verify green. Either approach:
- `cases/%.com` rule depends on `$(wildcard ../src/*.asm) $(wildcard ../inc/*.inc)` — conservative, rebuilds all on any src change.
- sjasmplus `--depend` output per case — surgical, but more Makefile machinery.

Conservative approach probably wins on simplicity. This is a follow-up story to schedule into Epic 3 prep.

### A2. Proactive NFR9 amend at Epic 3 planning (Ant agreed)

**Owner:** Story spec author (Amelia / John depending on planning skill used) | **Trigger:** Epic 3 planning pass

Suggested: **8192 B / 8 KB ceiling**, giving ~1900 B headroom for Epic 3's projected adds and leaving room for ARC/architectural surface that emerges during dev. Document amend history alongside the prior three amends in PRD §NFR9.
